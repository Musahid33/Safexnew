## 1. Method

| Check | How it was done |
| --- | --- |
| Orphaned source files | Every `.ts`/`.tsx` file compared against every import specifier in `app/`, `lib/`, `scripts/`, `tests/`. |
| Unused imports | Import statements stripped first, then each imported name counted in the remaining file body (avoids the "one import regex swallows the next" false positive). |
| Dead exports | Every exported symbol counted outside its own declaration **and** outside its own file, including `tests/` and `scripts/`. Category "entry" excluded (Next.js requires those). |
| Duplicate code | Normalised multi-line block comparison across files + every exported declaration name checked for a second definition. |
| Comments | All 1,908 comment lines read; duplicates and stale statements flagged. |
| CSS | Every class in `app/globals.css` cross-checked against TSX *and* generated markup, with dynamic/runtime-built names verified by hand. |
| Dependencies | Every `dependencies` / `devDependencies` entry matched to a real import; `tsconfig`-only packages checked separately. |
| Database | `pg_class`, `pg_attribute`, `pg_depend`, `pg_policy`, `pg_trigger`, `pg_proc` + per-table row counts, then each table and column cross-checked against `.from('…')` / `.rpc('…')` / select lists in the code. |

Baseline size: **51** app files / 10,504 lines · **46** lib files / 7,131 lines · **16** test files / 3,631 lines · **3** scripts / 587 lines · `app/globals.css` 168,931 B.

### 5.1 Internal-only exports — 70 (kept)

70 exported symbols are referenced only inside their own file. Examples: `lib/admin-reports.ts` `AdminReportPage`, `lib/dm/store.ts` `DmFetch`, `lib/content/store.ts` `DocumentRow`, `lib/employee-master/parse.ts` `normalizeIndianMobile`.

**Decision: keep the `export` keyword.** These are the natural module surface for the unit tests (which load modules through a small loader and may address symbols by name) and for the next feature that needs the same parser. Removing `export` would change 70 lines for zero runtime benefit while making those helpers untestable in isolation. This is deliberate, not an oversight.

`RootLayout`, `SafexHome`, `PublishPanel`, `RecognitionManager` are default exports consumed by the Next.js router.

## 10. Database

### 10.1 Usage

The application queries **13** tables: `employees`, `sites`, `reports`, `recognitions`, `site_announcements`, `report_attachments`, `documents`, `document_categories`, `daily_management_plans`, `site_events`, `employee_master_sync_runs`, `tenant_domains`, `tenants`, plus one RPC (`safex_consume_report_limit`, which touches `public_report_rate_limits`).

The schema has **38** base tables and **20** views. Every view has zero call sites — the app reads tables directly.

**No table qualifies as dead.** The only structurally isolated table, `push_subscriptions`, is the documented storage for the push rollout; the empty training/safety-alert/form-builder tables back screens that exist in the console; everything else is read through a view, written by a seed/audit RPC, or required by an RLS helper that guards the tables the app *does* use (`staff_memberships` and `safex_platform_admins` are referenced by `safex_can_manage_site`, `safex_has_site_access`, `safex_is_tenant_admin` and `safex_is_platform_admin`). Dropping that scaffold would be an architecture decision, not dead-code cleanup, and would be irreversible and break row-level security. Therefore **no table is dropped**.

### 10.3 Columns

Every all-NULL column except one is a live field: `employees.photo/email/gender/dob/notes/department/home_address/previous_names/emergency_contact_*/auth_user_id` are the editable profile fields behind the passport and the admin console; `documents.section/department/effective_date/review_due_date/mime_type/external_url` appear in the store's select lists and the register; `company_profiles.*` contact fields feed the About page; `sites.sos_backup_phone_e164`, `reports.worker_summary_approved`, `reports.client_submitted_at`, `recognitions.artwork_index` are read in code.

**Only `documents.uploaded_by` is unused**: all-NULL, zero references in code, views, indexes, policies and functions. It is an artefact of the original import and is dropped by `supabase/migrations/202610210007_drop_unused_document_author.sql` (applied to the live project).

### 10.4 Views

All 20 views are unqueried. Before dropping, each view name was matched against `app/`, `lib/`, `scripts/`, `tests/`, every `pg_policy` expression, every `pg_proc` body and the `pg_default_acl` table: **zero references**. The only dependency between them was the `companies` / `locations` compatibility views being selected by most `v_site_*` views, so those two are dropped last.

Dropped on 21 October 2026 by `supabase/migrations/202610210008_drop_unused_compat_views.sql` (applied to `mclrajfcrjdrlmoqwbdw`; `information_schema.views` now returns **0** rows for `public`). No base table, policy, function or grant was touched, and all 20 definitions remain in `20261020171922_safex_existing_schema_extension.sql` for restore. `docs/SUPABASE_SCHEMA_GUIDE.md` was rewritten to describe the base-table read paths.
